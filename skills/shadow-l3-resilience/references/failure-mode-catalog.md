# 9 维度失败模式目录（详细参考）

> L3 failure-modes.md 模板的详细参考。每条失败模式用 FMEA 字段描述。
> 标准模式 (S/M): 8 维 + 5 字段。扩展模式 (L): 9 维 (加跨地域/多活) + 8 字段 (加 Owner/SLO 关联/回滚时长)。

## 维度 1: 调度层（SCH）

调度层失败主要来自容器编排系统（Nomad / K8s / Swarm）和任务调度器（Celery / ARQ / Sidekiq）。

### F01: 调度风暴（Nomad / K8s 大量并发任务）

**触发条件**:
- 突发数据采集任务（采集车回传 / 用户上传）
- 周期性任务雪崩（多个 cron 同时触发）
- 客户端重试风暴

**爆炸半径**:
- 所有依赖调度的业务规则（采集/标注/仿真/报告）
- 上游用户（延迟/超时/失败）

**检测信号**:
- Nomad alloc 排队数 > 500
- K8s pending pod > 100
- 调度延迟 P99 > 5s
- 任务队列长度 > 1000

**兜底策略**（推荐组合）:
- L1 限流：token bucket, RATE_PER_SEC=10
- L2 优先级队列：CRITICAL/HIGH/NORMAL 三级
- L3 任务分批：BatchSize=100, Interval=10s
- L4 OOM 自杀：max_memory_mb=2048, 触发后 Nomad reschedule
- L5 健康检查摘除：连续 3 次失败从 service 中摘除

**恢复路径**:
- 自动：流量回落后，积压任务自动消化
- 半自动：监控告警后人工确认 Nomad 队列状态
- 紧急：清空队列（`nomad job stop -purge`）

**严重等级**: 高

---

### F02: 调度器宕机

**触发条件**:
- Nomad server / K8s API server 进程崩溃
- 调度器依赖的 etcd 故障
- 节点 OOM 杀掉调度器

**爆炸半径**:
- 所有任务调度停止
- 健康检查不更新

**检测信号**:
- Nomad server 健康检查 fail
- K8s API server `/healthz` 返回 5xx
- 节点心跳超时

**兜底策略**:
- L1 Nomad HA（3 server 部署，自动 failover）
- L2 K8s HA（multi-master）
- L3 应用层：检测到 scheduler down 时启用"只读模式"

**恢复路径**:
- 自动：Nomad HA failover < 30s
- 自动：K8s master 切换
- 人工：调度器 down 超过 5min 触发 PagerDuty

**严重等级**: 高

---

### F03: 节点失联

**触发条件**:
- 节点网络断开
- 节点硬件故障
- 节点 kernel panic

**爆炸半径**:
- 该节点上的所有任务
- 任务结果无法回传

**检测信号**:
- Nomad node status = down
- K8s node Ready = false
- 心跳超时 > 30s

**兜底策略**:
- L1 Nomad reschedule 到其他节点
- L2 任务幂等（重试不会产生副作用）
- L3 应用层：检测到任务在节点上超时未完成，重新调度

**恢复路径**:
- 自动：节点失联 > 5min 自动 reschedule
- 手动：节点恢复后标记 healthy, Nomad 自动 rebalance

**严重等级**: 中

---

### F04: Leader 脑裂

**触发条件**:
- 网络分区导致 etcd 选主不一致
- 调度器时钟漂移
- 存储故障导致选主数据不一致

**爆炸半径**:
- 多个"主"同时接受任务
- 数据冲突

**检测信号**:
- etcd quorum 告警
- 出现两个 Leader
- 数据写入冲突率上升

**兜底策略**:
- L1 严格 quorum（>= majority）
- L2 数据写入加 fencing token
- L3 业务层幂等（防止重复处理）

**恢复路径**:
- 自动：网络恢复后，etcd 重新选主
- 人工：脑裂期间的数据需手工合并

**严重等级**: 高

---

## 维度 2: 网络层（NET）

### F11: 网络分区

**触发条件**:
- 数据中心网络断开
- ISP 故障
- 防火墙规则错误

**爆炸半径**:
- 所有跨服务调用
- 所有依赖外部 API 的业务

**检测信号**:
- HTTP 超时率 > 30%
- TCP 连接失败率 > 10%
- 服务间延迟 P99 突增

**兜底策略**:
- L1 熔断器（5s 内 3 次失败触发 OPEN）
- L2 降级到本地降级存储
- L3 幂等重试（指数退避）
- L4 缓存上次成功结果

**恢复路径**:
- 自动：熔断器 HALF_OPEN 探测 → CLOSED
- 自动：草稿自动 sync 到主存储
- 手动：长时间无法恢复 → 切换到备用数据中心

**严重等级**: 高

---

### F12: 网络抖动

**触发条件**:
- 跨地域调用
- 无线网络不稳定
- ISP 拥塞

**爆炸半径**:
- 实时性要求高的业务
- 用户体验

**检测信号**:
- P99 延迟突增 10x
- 成功率下降但仍有成功

**兜底策略**:
- L1 超时（永远设上限）
- L2 缓冲（jitter buffer）
- L3 重试

**恢复路径**:
- 自动：网络恢复后延迟回归正常
- 人工：长期抖动考虑换 ISP / CDN

**严重等级**: 中

---

### F13: DNS 失效

**触发条件**:
- DNS server 故障
- DNS 缓存污染
- DNS 劫持

**爆炸半径**:
- 所有依赖 DNS 解析的调用

**检测信号**:
- nslookup / dig 超时
- 错误率突增

**兜底策略**:
- L1 DNS 缓存（TTL 控制）
- L2 IP 直连（关键服务）
- L3 健康检查摘除（DNS 解析失败的实例）

**恢复路径**:
- 自动：DNS 恢复后缓存自动更新
- 手动：长期失效 → 切换 DNS server

**严重等级**: 中

---

### F14: TCP 半开

**触发条件**:
- 网络设备丢包
- 客户端异常断电
- NAT 超时

**爆炸半径**:
- 连接池
- 长连接服务

**检测信号**:
- CLOSE_WAIT 状态连接数 > 100
- TIME_WAIT 持续累积
- 连接池耗尽

**兜底策略**:
- L1 TCP keepalive
- L2 应用层心跳
- L3 主动关闭空闲连接

**恢复路径**:
- 自动：连接自然关闭
- 手动：连接池满时强制重置

**严重等级**: 中

---

## 维度 3: 状态层（STA）

### F21: 状态漂移

**触发条件**:
- 多副本写入冲突
- 缓存与 DB 不一致
- 异步同步延迟

**爆炸半径**:
- 读路径规则
- 用户看到的数据可能不一致

**检测信号**:
- 版本号对比不一致
- 数据校验失败
- 用户反馈"刚才看的怎么变了"

**兜底策略**:
- L1 强一致读（关键路径）
- L2 版本号对比
- L3 重新加载

**恢复路径**:
- 自动：版本号对比触发重新加载
- 手动：数据校验发现不一致 → 触发全量对账

**严重等级**: 中

---

### F22: 版本冲突

**触发条件**:
- 并发写同一行
- 乐观锁冲突

**爆炸半径**:
- 写路径规则

**检测信号**:
- conflict 错误率 > 5%

**兜底策略**:
- L1 应用层重试（3 次）
- L2 冲突转失败 + 用户提示
- L3 分区写（按 user_id 哈希分片）

**恢复路径**:
- 自动：重试成功
- 手动：长期冲突 → 业务改造

**严重等级**: 低

---

### F23: 时钟漂移

**触发条件**:
- NTP 失同步
- 虚拟机时钟漂移

**爆炸半径**:
- 时间敏感业务
- 分布式锁
- 日志时间戳

**检测信号**:
- NTP server 偏移 > 1s
- 业务时间戳异常

**兜底策略**:
- L1 业务用 monotonic clock
- L2 关键路径 NTP 同步检查
- L3 分布式锁用 fencing token

**恢复路径**:
- 自动：NTP 同步后时钟回归
- 手动：严重漂移 → 重启服务

**严重等级**: 中

---

### F24: 缓存击穿

**触发条件**:
- 热点 key 过期
- 大量并发请求同一 key

**爆炸半径**:
- 读路径规则
- DB

**检测信号**:
- 同一 key QPS 突增
- DB QPS 突增

**兜底策略**:
- L1 singleflight（只允许一个请求查 DB）
- L2 后台预热（key 过期前 60s 重新加载）
- L3 永不过期 + 后台异步更新

**恢复路径**:
- 自动：key 重新加载后 QPS 恢复
- 手动：长期击穿 → 业务改造

**严重等级**: 中

---

## 维度 4: 资源层（RES）

### F31: OOM

**触发条件**:
- 大文件处理
- 内存泄漏
- 突发流量导致对象激增

**爆炸半径**:
- 全部业务（重启期间不可用）

**检测信号**:
- 内存使用 > 90%
- OOM killed 日志
- container exit 137

**兜底策略**:
- L1 限流（动态限流器，根据可用内存调整）
- L2 container restart_policy
- L3 健康检查摘除
- L4 业务拆分（大对象异步处理）

**恢复路径**:
- 自动：container 自动重启
- 手动：内存泄漏 → 修代码

**严重等级**: 高

---

### F32: 磁盘满

**触发条件**:
- 日志未清理
- 上传文件累积
- DB 表膨胀

**爆炸半径**:
- 写路径规则
- 日志写入

**检测信号**:
- df -h > 95%
- 日志写入失败

**兜底策略**:
- L1 自动清理（logrotate / 旧文件清理）
- L2 拒绝写
- L3 监控告警

**恢复路径**:
- 自动：清理后磁盘空间恢复
- 手动：扩展磁盘 / 清理 DB

**严重等级**: 高

---

### F33: 连接池耗尽

**触发条件**:
- 慢查询占用连接
- 突发流量

**爆炸半径**:
- 全部 DB 操作

**检测信号**:
- wait_count > 0
- 慢查询

**兜底策略**:
- L1 限流
- L2 队列降级
- L3 连接池监控

**恢复路径**:
- 自动：慢查询结束后连接释放
- 手动：长期耗尽 → 引入 pgbouncer

**严重等级**: 中

## 维度 5: 数据层（DAT）

### F41: DB 主从切换

**触发条件**:
- 主库硬件故障
- 主库 OOM
- 主库网络断开

**爆炸半径**:
- 写路径规则（短暂不可用）

**检测信号**:
- replica lag > 60s
- 应用层写失败

**兜底策略**:
- L1 应用层重试
- L2 自动检测新主
- L3 写降级（队列）

**恢复路径**:
- 自动：replica 检测到主失效 → 升级为新主
- 自动：应用层重试成功
- 手动：长期无法恢复 → 手工指定新主

**严重等级**: 高

---

### F42: 复制延迟

**触发条件**:
- 主库写压力
- 网络慢

**爆炸半径**:
- 读路径（读到旧数据）

**检测信号**:
- replica lag > 5s

**兜底策略**:
- L1 强制读主
- L2 监控告警

**恢复路径**:
- 自动：主库压力下降后延迟恢复
- 手动：长期延迟 → 业务改造 / 升级主库

**严重等级**: 低

---

### F43: 事务死锁

**触发条件**:
- 多个事务竞争同一资源
- 锁顺序不一致

**爆炸半径**:
- 写路径规则

**检测信号**:
- deadlock_detected 错误

**兜底策略**:
- L1 应用层重试
- L2 编码规范：固定锁顺序

**恢复路径**:
- 自动：死锁事务回滚
- 手动：频繁死锁 → 业务改造

**严重等级**: 低

---

### F44: 热点行

**触发条件**:
- 抢红包/秒杀
- 计数器高频更新

**爆炸半径**:
- 该行所属业务

**检测信号**:
- 单行 QPS > 100
- 锁等待 > 1s

**兜底策略**:
- L1 分片（按 user_id 哈希）
- L2 异步合并
- L3 内存计数 + 定时持久化

**恢复路径**:
- 自动：异步合并完成
- 手动：长期热点 → 业务改造

**严重等级**: 中

---

## 维度 6: 事件层（EVT）

### F54: 订阅者宕机

## 维度 7: 依赖层（DEP）

### F61: 第三方宕机

**触发条件**:
- 第三方服务故障
- 第三方 API key 失效
- 第三方限流

**爆炸半径**:
- 依赖该 API 的所有规则

**检测信号**:
- 第三方 5xx 率 > 50%
- 第三方响应超时

**兜底策略**:
- L1 熔断器
- L2 降级到 mock
- L3 缓存上次成功结果（TTL=1h）

**恢复路径**:
- 自动：第三方恢复 + 熔断器探测
- 手动：长期失效 → 切换备用第三方

**严重等级**: 高

---

## 维度 9: 跨地域/多活 (MRG) — L 规模扩展

> **本维度仅在 L 规模 (`l3_extended_mode: true`) 时必填。** 跨地域/多活部署是 L 规模项目(电商、支付、跨地域 SaaS)的核心,单地域的 8 维度发散无法覆盖机房级故障、跨地域一致性等关键失败模式。

### F81: 机房级故障

**触发条件**:
- 整机房网络断电
- 整机房空调/冷却故障
- 整机房 ISP 故障
- 雷击/火灾/地震等自然灾害

**爆炸半径**:
- 全部业务 (该机房内的所有服务)
- 该机房用户的全部请求

**检测信号**:
- 该机房所有实例健康检查批量失败
- 跨机房流量调度比例异常
- DNS 解析命中率下降

**兜底策略**:
- L1 跨地域 DNS 切换 (10s 内完成)
- L2 流量调度到其他机房
- L3 异地只读模式 (写操作排队)

**恢复路径**:
- 自动：DNS 切机房 + 流量重路由
- 半自动：监控告警后人工确认机房状态
- 手动：机房恢复后切回 (灰度 10%/50%/100%)

**严重等级**: 高

**Owner**: #infra-oncall
**SLO 关联**: 可用性 (99.99% SLA 必需)
**回滚时长**: 5min (自动) / 30min (手动)

---

### F82: 跨地域一致性违反

**触发条件**:
- 同订单在双机房同时写入
- 异地数据同步延迟导致读旧值
- Saga 跨地域事务部分机房失败
- 业务对账发现三方数据不一致 (订单/库存/支付)

**爆炸半径**:
- 资金类 (双扣/漏扣)
- 库存类 (超卖/少卖)
- 业务类 (订单状态错乱)

**检测信号**:
- 业务对账 inconsistencies > 0
- DB 双写 conflict 率 > 1%
- 跨机房同 key 写入冲突
- 业务对账 tolerance 超过 0 (资金类)

**兜底策略**:
- L1 业务对账 (跑批核对)
- L2 Saga 补偿 (跨地域回滚)
- L3 强制读主 (避免脏读)
- L4 人工对账 (异常单修复)

**恢复路径**:
- 自动：业务对账发现 → 自动修复
- 半自动：补偿失败 → 升级到 PagerDuty
- 手动：资金不一致 → 财务人工核对

**严重等级**: 高

**Owner**: #payment-oncall (资金) / #inventory-oncall (库存)
**SLO 关联**: 资金 / 合规
**回滚时长**: 5min (资金) / 1h (库存)

---

### F83: 异地数据同步延迟

**触发条件**:
- 跨地域主从复制网络抖动
- 跨地域主库写压力过大
- 跨地域网络中断 (部分)

**爆炸半径**:
- 读路径规则 (从库读旧值)
- 跨地域业务一致性

**检测信号**:
- replica_lag_seconds > 5
- 跨地域同步延迟 P99 > 阈值
- 一致性校验发现数据滞后

**兜底策略**:
- L1 监控告警 + 强制读主
- L2 跨地域只读 (用户就近接入读本地副本)
- L3 流量调度 (延迟高时调度到低延迟机房)

**恢复路径**:
- 自动：网络恢复后同步追赶
- 手动：长期延迟 → 主库扩容 / 跨地域专线升级

**严重等级**: 中

**Owner**: #infra-oncall
**SLO 关联**: 性能
**回滚时长**: 1h

---

### F84: 机房切换回滚

**触发条件**:
- DNS 切换后部分流量回切 (灰度切流不彻底)
- 灰度切流异常 (10%/50%/100% 比例错乱)
- 切机房后用户感知延迟上升

**爆炸半径**:
- 部分用户体验下降
- 切换期间服务不稳定

**检测信号**:
- 切流量比例异常
- 切机房后 P99 延迟上升
- 用户投诉增加

**兜底策略**:
- L1 灰度切流 (10%/50%/100% 三档)
- L2 自动回滚 (延迟不达标时)
- L3 人工监控 + 切回

**恢复路径**:
- 自动：延迟回退后自动回切
- 手动：人工判断后立即回切

**严重等级**: 中

**Owner**: #infra-oncall
**SLO 关联**: 可用性
**回滚时长**: 5min

---

### F85: 跨地域延迟

**触发条件**:
- 异地调用网络延迟 (>200ms)
- 跨地域专线拥塞
- 异地调用链路过长

**爆炸半径**:
- 用户体验 (跨地域用户延迟高)
- 实时性业务 (跨地域调用超时)

**检测信号**:
- 跨地域调用 P99 > 200ms
- 异地用户投诉增加
- 跨地域 timeout 率上升

**兜底策略**:
- L1 就近接入 (DNS 解析到地理最近机房)
- L2 边缘缓存 (跨地域只读数据走 CDN)
- L3 跨地域异步化 (写后即返回, 异步同步)

**恢复路径**:
- 自动：网络恢复后延迟回归
- 手动：长期延迟 → CDN 扩容 / 专线升级

**严重等级**: 中

**Owner**: #infra-oncall
**SLO 关联**: 性能
**回滚时长**: 1h

## 失败模式 ID 命名约定

`F` + 2 位数字 + 可选字母后缀（同一失败模式多个兜底）：

- F01: 主失败模式
- F01-a / F01-b / F01-c: 同一失败的多个兜底策略

**保留编号 (标准 8 维)**:
- F01-F09: 调度层
- F11-F19: 网络层
- F21-F29: 状态层
- F31-F39: 资源层
- F41-F49: 数据层
- F51-F59: 事件层
- F61-F69: 依赖层
- F71-F79: 流量层

**保留编号 (扩展 - L 规模 9 维)**:
- **F81-F89: 跨地域/多活 (L 规模扩展维度 9)**

## FMEA 8 字段完整模板 (L 规模)

| 字段 | 必填 | 类型 | 示例 |
|------|------|------|------|
| **触发条件** | ✅ | 字符串 | 下游 API 5s 内 3 次超时 |
| **爆炸半径** | ✅ | 字符串 | annotation-R03, collection-R05 (B01-N05/B02-N08) |
| **检测信号** | ✅ | 字符串 | http_client 超时率 > 30% |
| **兜底策略** | ✅ | 字符串 | 熔断 (5s) + 降级 (本地草稿) + 重试 (3 次指数退避) |
| **恢复路径** | ✅ | 字符串 | 熔断器 HALF_OPEN + 草稿自动 sync |
| **Owner** | ✅ (L) | 字符串 | #payment-oncall |
| **SLO 关联** | ✅ (L) | 多选 | 资金 / 可用性 / 性能 / 合规 |
| **回滚时长** | ✅ (L) | 时长 | 5min (资金) / 1h (性能) / 24h (合规) |

**SLO 类别说明**:
- **资金**: 0 容差, 必须 5min 内人工介入
- **可用性**: 99.9% SLA, 30min 内恢复
- **性能**: P99 延迟 SLO, 1h 内恢复
- **合规**: 审计追溯要求, 24h 内修复
