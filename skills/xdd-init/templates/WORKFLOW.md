## Project Header

本项目使用 **xdd 工匠型开发体系** (L0→L6 6 Phase 流程). 干活前必读:

- `.xdd/scale.md` — 规模 + strict_mode + halt_after
- `.xdd/current-iteration` — 当前 iter 编号
- `.xdd/iterations/{iter}/pipeline/status.md` — 阶段状态 (6 Phase 0→6)
- `.xdd/xdd-version` — 当前 xdd framework 版本

工件目录:
- `.xdd/baseline/` — 设计基线 (research / bdd / arch / wire)
- `.xdd/iterations/{iter}/` — 过程产物 (plan / design / verify / execute / pipeline)
- `.xdd/gates/` — 控制标记 (scale / current-iteration / xdd-version / .xdd-halt.json / .l0-review-block.md)

## 5-Step Rhythm (Walker 节奏)

```
① 装工具 (Skill 加载) → SKILL.md 自动注入上下文
② 写 checklist 到 status.md (30-50 行: 输入 / 产出 / 自检命令 / references)
③ 按工具流程干 (跟着 SKILL.md 的"怎么做"走)
④ 按需读 references/ (SKILL.md 里的指针指向哪就读哪个)
⑤ 自检 (跑 gate-check-xdd-*.sh) → 写状态到 status.md
```

## HARD-GATE 列表 (禁绕过)

- **L0 design gate** (实施 #22): 装 xdd-bdd / xdd-flow / xdd-wire / xdd-arch 前必验 `L0 design.md` 存在 + `.l0-review-block.md` 已删
- **6 闸门** (Phase 5): 任一不过 → halt (3 试 cap, halt_after 来自 scale.md)
- **L3 chaos** (实施 #20): 5 类真注入 (network / resource / state / data / dependency) L 规模必跑
- **跨服务真链路** (实施 #1): `--cross-service-real-path` mode, producer→queue→consumer→DB 真跑
- **Phase 6 → 5 回退** (实施 #18): L5 audit / R11 L4 fail → `updateStageStatus(5 Execute, ❌ late-fail)`, 不放回 ✅
- **Stub-scan 语义层** (实施 #19): unmounted_router / unconsumed_queue / dockerfile_drift / unregistered_error_code
- **FINAL-DELIVERY 拆分** (实施 #21): 必分 ✅ 原计划 + ⚠️ Late Fix 2 段, 跟 status.md 一致性闸门

## 风格偏好

- **no-advisory**: 闸门不通过 = 必修, 不放回 "基本通过"
- **YAGNI ruthlessly**: 砍不必要功能, 写到 design.md §Out of Scope
- **halt on 3 tries**: 同一 P1 连续 3 试未修, 强制回退到设计层 (5 marker ⏳/🔄/✅/❌/🚧)
- **自治决策**: 简单默认 walker 自主, 写到 design §Assumptions; 关键决策走 §Open Questions 必 user 审
- **状态机优先**: status.md 是 working memory, 每个 tool swap + stage 完成都更新
- **design 必走**: L0 → design.md (Selected / Alternatives / Assumptions / Out of Scope / Open Questions 5 段) → spec review → block.md → user 审 → 才可 xdd-bdd
