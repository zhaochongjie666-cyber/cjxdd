# UX 审查框架（深度透镜）

> 复杂页面做 Step 3 攻击式 review 时，用这 4 级框架系统过一遍。
> 源自《UX 设计的艺术与科学》(Anthony Conta) 设计思维六步法，转译为前端审查清单。

## 心法

UX = 艺术 × 科学。每个交互决策回答两问：**用户感受到什么？** + **我们怎么知道它有效？**

设计思维六步：共情（谁在用/什么场景）→ 定义（解决什么问题）→ 构思（2-3 种方案）→ 原型（最简形态验证）→ 测试（真实走查）→ 实施（可度量指标）。

## 4 级审查（从致命到精致）

### 🔴 L1 功能性（不通过则不可用）

| 检查点 | 失败信号 | 修复 |
|---|---|---|
| 任务可完成性 | 不知道点哪完成主任务 | CTA 视觉显著、文字明确 |
| 错误反馈 | 失败无提示/不明确 | 所有失败路径有可读错误 + 下一步 |
| 状态可见 | 不知道在加载/成功/失败 | loading/success/error 三态明确 |
| 防破坏性 | 删除无确认 | 二次确认，默认焦点在"取消" |
| 键盘可达 | 鼠标可用键盘不可用 | 所有交互 Tab 可达，Enter/Space 触发 |

### 🟡 L2 可用性（不通过则难用）

| 检查点 | 检查 | 修复 |
|---|---|---|
| 一致性 | 相似功能用相似模式 | 组件库统一按钮/表单/弹窗行为 |
| 信息层次 | 第一眼看出谁最重要 | 大小/颜色/间距建 3 层视觉层次 |
| 认知负荷 | 单屏元素过多 | 格式塔分组（接近/相似/封闭） |
| 反馈即时性 | 操作后多久感知变化 | <100ms 瞬时；>1s 必 loading |
| 撤销与返回 | 误操作能否挽回 | Undo/Back/Exit |
| 移动端可用 | 触控目标够大吗 | 最小 44×44px，间距防误触 |
| 文案清晰度 | 有歧义吗 | 动词开头、避免术语、说结果不说过程 |

### 🟢 L3 可达性 a11y（不通过则排他）

| 检查点 | 标准 |
|---|---|
| 语义化标签 | `<button>`/`<a>`/标题层级正确 |
| ARIA | 图标按钮 `aria-label`、动态区 `aria-live` |
| 颜色对比度 | 文字背景 ≥ 4.5:1（大字 3:1） |
| 焦点可见 | 键盘聚焦有清晰 outline（别 `outline:none`） |
| 替代文本 | 图片有 `alt`，装饰图 `alt=""` |
| 表单可访问 | label 关联 input（`<label for>`） |
| 减少动效 | 尊重 `prefers-reduced-motion` |

### 🔵 L4 体验质感（情感层）

微交互（hover/active/disabled 反馈）/ 动效合理（帮理解非炫技）/ 空状态（友好引导非空白）/ 加载体验（skeleton 还是转圈）/ 成功庆祝（toast/动画）/ 品牌一致（配色字体语气统一）。

## 10 个高频反模式（必须规避）

1. **鬼按钮**：按钮看着像文字或链接，或反之
2. **无限滚动没尽头**：用户不知在哪、要多久
3. **模态套模态**：多层弹窗嵌套，用户迷失
4. **占位符代标签**：只用 placeholder 没 label（聚焦即消失）
5. **错误只说"失败"**：不说为什么、怎么办
6. **加载态消失但内容未到**：瞬间空白闪烁
7. **响应式只断大屏**：平板/折叠屏崩坏
8. **图标无标签**：纯图标按钮没文字或 aria-label
9. **必填项没标记**：提交后才报错，而非进入时就知道
10. **暗模式只是反色**：对比度色相未调，伤眼

## 反馈方法（走查时）

**给予**：先肯定后建议 → 具体（"主次操作视觉权重太近"而非"不好看"）→ 对事不对人 → 给 ≥2 替代方案 → 用 L1/L2/L3/L4 标严重性。

**接收**：先听完再回应 → 问澄清（"你说的'奇怪'具体哪瞬"）→ 区分观点与数据 → 全记下来事后筛 → 改完闭环。

## 一句话

> 好的 UX 不是好看的界面，而是让用户忘记界面存在的体验——达成目标时直接离开，而不是赞叹"设计真好"。
