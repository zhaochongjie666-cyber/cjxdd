# L1 Semantic Gate Prompt

用于 L1 第二轨 Gate（独立语义审查）。

## 输入
- `research.md`
- `flow.mermaid`
- `spec.md`
- `wire.svg` SVG UI/UX 契约图

## 目标
判断 L1 是否同时满足：
1. **实现指导性**：L5 能否直接开始实现？
2. **人类可读性**：产品/业务/测试是否能直接读懂并复核？
3. **业务完整性**：是否覆盖主流程、异常、边界、权限、状态、依赖、副作用？

## 审查问题（必须逐项回答）
1. 仅看 L1，工程师是否能明确接口/动作、状态、校验、错误、依赖和副作用？
2. 规则是否存在大量抽象空话，如“系统处理”“必要时通知”“失败则提示错误”？
3. spec 是否覆盖 happy path 之外的失败、拒绝、超时、重试、幂等、回滚、人工兜底？
4. 规则标题、状态名、按钮名、错误文案是否优先使用业务语言，而非纯工程黑话？
5. flow / spec / wire 三者是否相互对齐？
6. 业务对象生命周期是否清楚？是否有关键状态缺失？
7. 数据约束和外部依赖是否足够具体，足以指导实现？
8. `wire.svg` 是否能看出所有页面/弹窗/抽屉、所有可交互点、关键状态、反馈和跳转/API 目标？
9. `wire.svg` 是否具备 `data-page/data-route/data-node/data-rule/data-action/data-target/data-state` 或 metadata/desc，实现者能直接传导到代码？
10. 如果把这份 L1 交给一个没参与需求讨论的新工程师，他是否还会追问大量关键问题？如果会，缺口是什么？
11. `给 L1.5 / 给 L2 / 给 L5` 这些交接输入是否具体、可执行，还是只是在复述前文？
12. 下游如果严格按照这些交接输入工作，是否会在模块边界、测试断言、实现约束上掉链子？

## 品味维度审查（第 13-15 题）

13. 删掉 L1 交付物 30% 的内容，核心传导是否断裂？不断裂 → 冗余过多。
14. 不熟悉业务的新人读 5 分钟能理解核心吗？不能 → 信息密度不够。
15. 随机抽 3 个术语，在 research/flow/spec/wire 中是否完全一致？不一致 → 品味断裂。

## 输出格式
```markdown
## L1 Semantic Gate Report: <slug>

- Verdict: PASS / FAIL
- Summary: 一句话总结

### PASS 依据
1. ...
2. ...
3. ...

### FAIL / 风险点
1. [实现指导性 / 人类可读性 / 业务完整性] 问题描述
2. ...

### 交接吸收判断
1. [L1.5 / L2 / L5] 哪些交接输入已经足够直接消费？
2. [L1.5 / L2 / L5] 哪些交接输入仍然抽象、模糊或存在断层？

### 必改项
- ...
```

## 判定规则
- 只要"实现指导性 / 人类可读性 / 业务完整性"中任一项明显不足，直接 FAIL。
- 品味维度 13-15 中有 ≥2 条不通过 → 品味不足 WARN。
- 品味维度 13-15 中 3 条全不通过 → 品味不足 FAIL。
- 不允许只给笼统评价，必须给具体证据。
