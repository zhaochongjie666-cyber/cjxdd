## §1 Q1-Q5 攻击式问题（复用 wire · 单页面）

逐个按钮/区域/交互问：

- **Q1 这个元素为什么要存在？** —— 用户不知道功能存在呢？有更自然的方式吗？→ 保留/修改/删除
- **Q2 这个数字是什么范围？** —— 用户能判断「今日/本周/累计」吗？没上下文就加时间范围标注
- **Q3 两个相似元素行为一致吗？** —— 外观像的，行为也得像；不像就区分外观
- **Q4 第一次用的用户看得懂吗？** —— 列出内部术语/缩写/黑话，翻译成用户语言
- **Q5 有没有「一次性」交互没告知？** —— 只该做一次的操作有没有明确引导

## §2 L1-L4 四级审查（复用 wire）

### 🔴 L1 功能性（不通过则不可用）

| 项 | 坏信号 | 好信号 |
|----|--------|--------|
| 任务可完成性 | 不知道点哪完成主任务 | CTA 视觉显著、文字明确 |
| 错误反馈 | 失败无提示/不明确 | 所有失败路径有可读错误 + 下一步 |
| 状态可见 | 不知道在加载/成功/失败 | loading/success/error 三态明确 |
| 防破坏性 | 删除无确认 | 二次确认，默认焦点在「取消」 |
| 键盘可达 | 鼠标可用键盘不可用 | 所有交互 Tab 可达，Enter/Space 触发 |

### 🟡 L2 可用性（不通过则难用）

| 项 | 坏信号 | 好信号 |
|----|--------|--------|
| 一致性 | 相似功能用不同模式 | 组件库统一按钮/表单/弹窗行为 |
| 信息层次 | 第一眼看不出谁重要 | 大小/颜色/间距建 3 层视觉层次 |
| 认知负荷 | 单屏元素过多 | 格式塔分组（接近/相似/封闭） |
| 反馈即时性 | 操作后不知道变化 | <100ms 瞬时；>1s 必 loading |
| 撤销与返回 | 误操作无法挽回 | Undo/Back/Exit |
| 移动端可用 | 触控目标太小 | 最小 44×44px，间距防误触 |
| 文案清晰度 | 有歧义 | 动词开头、避免术语、说结果不说过程 |

### 🟢 L3 可达性 a11y（不通过则排他）

| 项 | 坏信号 |
|----|--------|
| 语义化标签 | `<button>`/`<a>`/标题层级错乱 |
| ARIA | 图标按钮无 aria-label，动态区无 aria-live |
| 颜色对比度 | 文字背景 < 4.5:1（大字 3:1） |
| 焦点可见 | `outline:none` 去掉键盘聚焦 |
| 替代文本 | 图片无 alt，装饰图 alt 非空 |
| 表单可访问 | label 未关联 input |
| 减少动效 | 不尊重 prefers-reduced-motion |

### 🔵 L4 体验质感（情感层）

微交互（hover/active/disabled 反馈）/ 动效合理（帮理解非炫技）/ 空状态（友好引导非空白）/ 加载体验（skeleton 还是转圈）/ 成功庆祝（toast/动画）/ 品牌一致（配色字体语气统一）

## §3 混淆元素四类扫描（复用 wire）

逐页面扫「看起来像但实际不同」的元素：

- **A 视觉混淆** —— 颜色/形状/位置像，但功能不同
- **B 语义混淆** —— 名字像，但含义不同
- **C 交互混淆** —— 操作像，但行为不同
- **D 内容混淆** —— 数据展示像，但来源/范围不同

## §4 10 高频反模式（复用 wire）

逐页面核对：

1. **鬼按钮** —— 按钮点了没反应（handler 没绑 / disabled 但没视觉区分）
2. **无限滚动没尽头** —— 滚到底没 footer，没「到底了」提示
3. **模态套模态** —— 弹窗里又弹弹窗（焦点陷阱 + 层级混乱）
4. **占位符代标签** —— placeholder 当 label 用（输入后忘了字段叫啥）
5. **错误只说「失败」** —— 没原因没下一步
6. **加载态消失但内容未到** —— loading 结束了但内容还没渲染（空白闪现）
7. **响应式只断大屏** —— 只适配手机/桌面，平板/折叠屏崩
8. **图标无标签** —— 纯图标按钮，用户猜不到功能
9. **必填项没标记** —— 提交了才知道哪个必填
10. **暗模式只是反色** —— 暗模式直接反色，对比度/语义色全乱

## §5 跨页面维度（polish 独有 · wire review.md 没覆盖）

wire 的 review.md 是单页面自审。polish 补**全局**视角：

### 5.1 跨页面流程连贯性

**质询**：用户从 A 页到 B 页，上下文接得住吗？

- 跳转后状态丢失？（列表筛选条件 → 详情页 → 返回 → 筛选没了）
- 跳转突兀？（无过渡、无面包屑、不知道自己在哪）
- 表单跨页填写的数据保不保留？
- 错误页后能回到原流程吗？还是回首页重走？

### 5.2 全局视觉一致性

**质询**：不同页面配色/字体/间距/组件统一吗？

- 设计系统漂移？（A 页按钮圆角 4px，B 页 8px，C 页直角）
- 颜色语义一致吗？（A 页红色 = 错误，B 页红色 = 重点）
- 字体层级跨页一致吗？（A 页 h1 = 24px，B 页 h1 = 20px）
- 间距规律统一吗？（有的页面 8px 栅格，有的乱来）

### 5.3 6 态覆盖全局视图

**质询**：哪些页面漏了哪态？（empty/loading/error/success/confirm/edge）

画全局矩阵：

| 页面 | empty | loading | error | success | confirm | edge |
|------|-------|---------|-------|---------|---------|------|
| 列表页 | ✓ | ✓ | ? | — | — | ? |
| 详情页 | ? | ✓ | ? | — | — | ? |
| ... | | | | | | |

漏的态 = 攻击点（edge 态尤其容易漏：无权限/配额耗尽/离线）。

### 5.4 首用户旅程

**质询**：完全没上下文的新用户，能从首页走到核心功能完成吗？

- 首页告诉新用户「这能干啥」吗？
- 核心流程有引导吗？（第一次用要不要教程/空状态引导）
- 注册→登录→首次配置→核心动作，每步衔接顺吗？
- 有没有「假设你已经知道」的隐式前提？（专业术语、内部缩写）

## 攻击点定级

- **P0** = 阻断核心流程（用户完成不了主任务）。例：核心 CTA 鬼按钮、错误态无返回路径、必填项无标记导致反复失败。
- **P1** = 严重体验缺陷。例：缺加载态、错误只说「失败」、模态套模态、跨页状态丢失。
- **P2** = 体验质感改进。例：缺微交互、动效炫技、暗模式反色、a11y 对比度不足。

每条攻击点三件套：**为什么是问题（用户怎么受挫）+ 证据（wire/{page}/index.html:行号）+ 怎么改（指向 xdd-wire）**。
