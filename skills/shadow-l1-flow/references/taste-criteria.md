# 品味标准 — Apple 设计哲学映射

品味 = 精确 + 克制 + 信息密度。100 字能说清的不用 1000 字。

## 六原则 × 五层映射

### Minimalism — 删到不可再删

| 层 | 检验 |
|---|------|
| L0 发散 | 不适用。发散笔记本无品味约束、无门禁、不评判。 |
| L1 Research | 意图 ≤ 一句话。收敛后画像 ≤ 8 个。旅程精简但全面。 |
| L1 Flow | 泳道 ≤ 10 节点。删节点后流程仍通 → 删。 |
| L1 Spec | 删规则后下游无影响 → 删。删前置条件后仍成立 → 删。 |
| L1 Wire | 去掉 30% 元素后核心功能仍可达 → 当前的 30% 是冗余。 |
| L5 Harness | 每个方法指令 ≤ 20 行。超过 → 拆方法。 |
| L5 Impl | 函数 ≤ 20 行，参数 ≤ 3 个。 |

### Invisible Care — 异常路径是尊重，不是负担

| 层 | 检验 |
|---|------|
| L0 发散 | 不适用。发散笔记本记录所有异常假设，不评判。 |
| L1 Research | 每条主线步骤问"断了/错了/挂了怎么办"。收敛时只保留关键异常。 |
| L1 Flow | 每个决策节点有否定分支。外部依赖有降级路径。 |
| L1 Spec | 异常写用户能懂的话，不写裸 HTTP 状态码。 |
| L1 Wire | 空态有引导，错误态有行动建议。 |
| L5 Harness | 每个方法的每个校验失败路径都有错误码 + 测试断言。 |
| L5 Impl | 错误不吞、可发现、可解释。 |

### Serve Humans — 写人话，不写系统话

| 层 | 检验 |
|---|------|
| L0 发散 | 不适用。发散笔记本鼓励自由表达，不限语言风格。 |
| L1 Research | 画像有人物感。旅程有心流。 |
| L1 Flow | 节点命名用"动词+宾语"，不写"处理""判断"。 |
| L1 Spec | "标注员可提交"优于"用户可提交"。 |
| L1 Wire | 按钮文案说清楚点击后会发生什么。 |
| L5 Harness | 不写设计上下文，只写 coder 需要的技术指令。 |
| L5 Impl | 代码自解释，注释只写 Why 不写 What。 |

### Global Consistency — 同一个词，从头到尾

| 层 | 检验 |
|---|------|
| L0 → L1 | 发散笔记中的术语在收敛后统一为 L1 统一语言。 |
| 全层 | 术语 = research.md 统一语言。同义词 = 品味缺口。 |
| L1 Wire | Header/Sidebar/按钮高度/字体/圆角全局统一（±2px）。 |
| L5 Harness | 类名/方法名/事件名与 L1 统一语言一致。 |

### Process as Material — 数据流转即设计

| 层 | 检验 |
|---|------|
| L1 Flow | 节点标注 read/write/external。write 节点标注 idempotent。 |
| L1 Flow | 决策条件可判定：有量纲、有数据源、无元描述。 |
| L1 Wire | 布局从用户旅程推导，不凭感觉。 |
| L5 Harness | 每个方法标注状态变更 + 事件发布 + 错误码。 |

### Refinement — 写完再删一遍

| 层 | 检验 |
|---|------|
| L0 → L1 | 发散笔记的 80% 内容在收敛后被丢弃。这是正常的。 |
| 全层 | 删除冗余描述后下游仍可开工 → 删对了。 |
| L5 Harness | Harness 计划中无 spec 业务上下文重述，只有 coder 技术指令。 |
| 文档 | 100 字能说清的不用 1000 字。信息密度 > 信息量。 |

## 致命三检

每层交付前必过。不通过 = 门禁不通过。

1. **减法检验**：删掉 30% 内容，核心传导是否断裂？不断裂 → 冗余过多。
2. **人话检验**：给不熟悉业务的新人看，5 分钟能理解核心吗？不能 → 信息密度不够。
3. **一致检验**：随机抽 3 个术语跨层搜索，是否完全一致？不一致 → 品味断裂。

### L0 发散笔记本豁免

L0 笔记本**不适用**致命三检。发散笔记本的目的是记录所有想法，不评判质量、不检查品味、不设门禁。致命三检从 L1 收敛开始适用。

## 发散/收敛品味约束

### L0 发散 — 自由记录，不评判

- 无格式要求、无品味约束、无门禁
- 目的：穷尽可能性，记录所有假设和异常
- 不直接被下游消费

### L1 收敛 — 精确提取，丢弃过程

- 从 L0 笔记中提取关键结论，丢弃中间过程
- 收敛后画像 ≤ 8 个（合并到区分度检验不通过为止）
- 收敛后旅程精简但全面（关键旅程，不是全量旅程）
- 外部调研结论必须收敛为来源表 + 可借鉴模式 + 已知陷阱

### L5 Harness — 精密但不冗余

- 每个方法指令 ≤ 20 行（超过 → 拆方法）
- 不重复 spec 的业务上下文，只保留 coder 需要的技术指令
- coder 看到每个方法指令后能在 30 秒内开始写代码
- 测试断言覆盖：正常路径 + 每个校验失败路径

## Flow 特化品味约束

泳道 ≤ 10 节点。单个泳道决策节点 ≤ 3（超过说明职责过多）。每个决策节点有否定分支。节点标注 read/write/external/idempotent。

### 决策条件精确性（AI 能写 if 吗？）

| 品味等级 | condition 写法 | 示例 |
|---------|---------------|------|
| **无品味** | 元描述 | `quality check passed` |
| **有品味** | 具体可判定表达式 | `title.length >= 5 & body.length >= 100 & no banned_words` |

判断标准：AI 看到 condition → 能直接写 `if (title.length >= 5 && ...)` → 通过。需要"理解上下文"才能写 → 不通过。

### 幂等标注（AI 不说不做）

每个 write 节点必须有 `idempotent:` 标注。缺少 = AI 不会写幂等逻辑 = 并发时出 bug。

## 文档品味

- 检查项 ≤ 3 条，每条都致命
- 正反示例比抽象原则有力
- 品味标准本身也必须遵守品味标准
