# 用户登录功能 - 需求分析文档

## 1. 功能概述

实现用户登录模块，支持多种登录方式，为系统提供统一的身份认证与授权能力。

## 2. 支持的登录方式

| 方式 | 优先级 | 说明 |
|------|--------|------|
| 账号密码登录 | P0 | 用户名/邮箱 + 密码，核心功能 |
| 手机验证码登录 | P1 | 手机号 + 短信验证码 |
| 第三方 OAuth 登录 | P1 | 微信、GitHub、Google 等 |

## 3. 核心功能需求

### 3.1 账号密码登录（P0）

- 用户通过用户名或邮箱 + 密码登录
- 密码错误时提示"用户名或密码错误"（不泄露具体原因）
- 连续 5 次失败后锁定账号 15 分钟
- 支持"记住我"功能（延长 Token 有效期至 30 天）

### 3.2 手机验证码登录（P1）

- 输入手机号，发送 6 位数字验证码
- 验证码有效期 5 分钟，同一手机号每分钟限发 1 次
- 新手机号自动注册并登录

### 3.3 第三方 OAuth 登录（P1）

- 支持微信、GitHub、Google OAuth2.0 授权
- 首次授权自动创建账号并关联
- 已有账号可绑定/解绑第三方账号

### 3.4 注册

- 支持用户名 + 邮箱 + 密码注册
- 邮箱验证（发送激活链接）
- 用户名唯一性校验
- 密码强度要求：8-32 位，至少包含字母和数字

### 3.5 忘记密码

- 通过注册邮箱发送重置链接（有效期 1 小时）
- 重置链接使用后立即失效

### 3.6 登出

- 清除服务端会话/Token
- 清除客户端存储的凭证

## 4. 非功能需求

| 维度 | 要求 |
|------|------|
| 安全性 | 密码使用 bcrypt 加密存储（cost factor >= 12）；JWT Token 签名；HTTPS 传输 |
| 性能 | 登录接口响应时间 < 500ms（P99） |
| 可用性 | 登录服务可用性 >= 99.9% |
| 兼容性 | 支持 Chrome/Firefox/Safari/Edge 最新 2 个主版本 |
| 并发 | 支持单节点 1000 QPS |

## 5. 认证方案

- **Token 类型**: JWT (Access Token + Refresh Token)
- **Access Token 有效期**: 2 小时
- **Refresh Token 有效期**: 30 天（可配置）
- **存储位置**: Access Token 存于内存/cookie；Refresh Token 存于 HttpOnly cookie

## 6. 接口列表（初步）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/auth/login | 账号密码登录 |
| POST | /api/auth/sms-login | 手机验证码登录 |
| POST | /api/auth/oauth/{provider} | 第三方 OAuth 登录 |
| POST | /api/auth/register | 用户注册 |
| POST | /api/auth/logout | 登出 |
| POST | /api/auth/refresh | 刷新 Token |
| POST | /api/auth/forgot-password | 忘记密码 |
| POST | /api/auth/reset-password | 重置密码 |
