# UAT 剧本详细指南

> **边界澄清 (2026-06-07 P0-X Round 2 起)**: UAT 剧本 (uat-script.md) 跟
> `production-scenarios/` 是**互补不重复**的两层产物.
> - UAT = 用户视角 Markdown 剧本 (L6 Phase 7 现场跑, 人工/Playwright 验证)
> - Production Scenarios = 可执行 Playwright spec.ts 套件 (L6 Phase 5.8 自动跑, 跟生产一致)
>
> L2 walker 两者都必须产出, L6 两者都必须跑. 一者通过 ≠ 另一者通过.
> Production Scenarios 失败 → R11 硬阻断, 即便 UAT 100% PASS.
> 详见 `production-scenario-contract.md` § 9 跟 uat-script.md 的边界表.

## UAT 剧本结构

每个业务线在 `.shadow/L2-e2e/BXX-{slug}/uat-script.md` 产出用户验收剧本。

```markdown
# <slug> 用户验收剧本

## UAT-01：<真实用户目标>

**用户目标**: <用户实际想完成的工作，不写技术目标>
**角色**: <真实角色，如管理员/标注员/审核员>
**浏览器入口**: <完整 URL，如 http://localhost:3000/login>
**涉及流程节点**: BXX-NYY -> BXX-NYY -> BXX-NYY
**涉及规则**: R01, R02, R03
**覆盖页面**: <wire.svg data-page 列表>
**验收数据**:
- 用户账号: <角色账号>（用于浏览器登录）
- 业务数据: <真实字段、真实规模、真实状态>
- 外部依赖: <短信/邮件/OAuth/支付/通知，如适用>
- 浏览器持久化断言: <操作后在浏览器页面中能看到什么>
- 数据库持久化断言: <DB/API 层面的最终数据状态>
- 重启后断言: <如为 P0，重启服务后在浏览器中重新查询仍可见>

### 浏览器操作脚本（每一步对应 Playwright 操作）
1. 打开浏览器，访问 `<URL>`。→ `playwright open <URL>`
2. 在用户名输入框输入 `<account>`，密码框输入 `<password>`，点击"登录"按钮。→ `fill` + `click`
3. 等待页面跳转到首页，确认首页加载完成（看到导航栏）。→ `waitForURL` + `waitForSelector`
4. 在导航栏中点击"<菜单名>"，等待目标页面加载。→ `click` + `waitForLoadState`
5. 在目标页面中，<点击/填写/选择/拖拽/上传具体元素>。→ `click`/`fill`/`select`/`drag`/`upload`
6. 等待操作反馈（loading 消失，成功/错误提示出现）。→ `waitForSelector`
7. 在浏览器中确认操作结果（页面文字/列表更新/状态标签变化）。→ `assertText`/`assertVisible`
8. [如为 P0] 打开新标签页，访问查询页面 URL，确认数据可查。→ `open` + `assert`
9. [如为 P0] 重启服务后，在浏览器中刷新页面，确认数据仍在。→ `reload` + `assert`
10. 点击右上角头像，选择"退出登录"。→ `click`

### 通过标准
- 浏览器页面反馈: <每一步用户在浏览器中看到什么>
- 浏览器数据可见: <操作后列表/详情可见的最终状态>
- 数据库一致: <DB/API 查询结果与浏览器页面显示一致>
- 副作用验证: <浏览器通知/邮件截图/文件下载等>
- 错误处理: <失败时浏览器显示什么，用户如何修正>
- 浏览器网络请求: <关键 API 请求 URL、方法、状态码>

### 证据要求
- 浏览器截图: 每个关键步骤（起始页、操作中、操作后反馈、最终结果页）
- 浏览器网络: 关键 API 请求 URL、方法、状态码
- 数据证据: API 响应/DB 查询/导出文件校验
- 日志证据: 如涉及异步任务或外部服务
```

## UAT 通过门槛

- 每个核心角色必须有 UAT 剧本覆盖其所有核心目标
- 每条核心业务主链路必须有 UAT 覆盖所有分支路径
- 数量不设上限，每条旅程穷举结果都落实到 UAT
- 每条 UAT 串联 ≥3 个 BXX-NYY 节点
- 每条 UAT 覆盖 ≥2 条 RXX 规则
- 操作用浏览器语言描述，能翻译为 Playwright 交互
- P0 UAT 包含真实持久化 + 重启后查询
- 每条 UAT 包含浏览器可见反馈验证
- 每条 UAT 包含导航路径（从登录到目标页面完整点击路径）
- 每条 P0 UAT 包含至少 1 个误操作验证

## UAT 剧本示例

### P0: 标注员完成标注提交

```markdown
## [P0] UAT-04: 标注员完成 2D 标注并提交质检

**前置**：采集任务已完成上传，标注任务已分配给标注员 annotator1。

**步骤**：
1. 登录标注员账号 annotator1 → assert: 跳转到任务列表页
2. 在任务列表点击"标注任务 #T001" → assert: 标注编辑器加载，画面区域可见
3. 点击"+ 创建标注"按钮 → assert: 标注工具面板出现
4. 在画面上拖拽创建矩形框 → assert: 矩形框可见，标签选择器出现
5. 选择标签"car" → assert: 标签显示为"car"
6. 点击"保存" → assert: 标注保存成功
7. 点击"提交质检"按钮 → assert: 确认弹窗出现
8. 点击"确认提交" → assert: 成功提示"已提交质检"，任务状态变为 SUBMITTED

**证据**：截图 4 张（标注工具面板 / 标注完成画面 / 提交确认弹窗 / 提交成功提示）
```

### P0: 采集员外场采集+打点

```markdown
## [P0] UAT-01: 采集员创建任务并完成采集

**前置**：系统已启动，采集员账号 collector1 已登录。

**步骤**：
1. 打开采集地图页 → assert: 地图加载，"新建采集"按钮可见
2. 点击"新建采集" → assert: 采集任务表单出现
3. 填写路线"园区北路测试"、区域"高新区" → assert: 表单字段已填写
4. 点击"创建" → assert: 任务创建成功，状态显示 DRAFT
5. 点击"开始采集" → assert: 状态变为 COLLECTING，打点按钮激活
6. 在地图上点击"记录打点" → assert: 打点标记出现在地图上
7. 再次点击"记录打点" 2 次 → assert: 地图上有 3 个打点标记
8. 点击"结束采集" → assert: 确认弹窗出现
9. 点击"确认结束" → assert: 状态变为 FINISHED，上传进度条出现

**证据**：截图 4 张（表单填写 / 采集中+打点 / 确认结束 / 上传进度）
```
