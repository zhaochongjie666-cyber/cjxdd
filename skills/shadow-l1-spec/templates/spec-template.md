## 规则 6 要素

每条规则必须包含：

1. **规则标题** — FDD 格式：`<verb> the <object>`（如 "Calculate the total order amount"）
2. **业务意图** — 为什么需要这条规则
3. **触发条件** — 什么情况下触发（具体到用户操作/事件）
4. **前置条件** — 触发前必须满足的条件
5. **执行动作** — 具体执行什么（API 调用/状态变更/领域事件发布）
6. **预期结果** — 执行后的具体可观测结果

## 约束

- 每条规则必须有对应状态变化（R→S 映射）
- 异常处理必须具体到错误码和用户提示文案
- 规则 ID 格式：`{slug}-R01`、`{slug}-R02`、...（连续无跳号）
- 每条规则标注 BXX-NYY 节点坐标
- 规则必须按聚合根分组（Feature Set）
- 领域模型标注必须与 research.md DDD 建模保持一致
- `用户可见` 必须显式标明用户是否能直接看到该动作/状态/反馈
- `需 Wire 承接` = `是` 的规则，必须在 `wire.svg` 中有对应 `data-node`、`data-rule`、`data-action`、`data-target` 和状态反馈
