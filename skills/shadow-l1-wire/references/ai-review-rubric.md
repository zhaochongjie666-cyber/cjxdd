# AI Review Rubric

这份文档定义 `Wire SVG` 的 AI 审查评分标准。

目标不是让模型输出“看起来像 review”，而是让团队可以比较：

- 不同模型谁更稳
- 不同 prompt 谁更有效
- 同一个模型在不同页面类型上的表现是否一致

## 1. 适用范围

这份 rubric 适用于审查以下材料组合：

1. `wire.svg`
2. `spec.md` 中 UI 承接相关部分
3. `project.flow.mermaid`

它不评价代码实现质量，只评价 `L1 Wire SVG` 的审查质量。

## 2. 评分维度

总分建议 `20` 分，分成 5 个维度，每项 `0~4` 分。

### A. 问题分层

判断模型是否清楚区分：

- 确定性问题
- 语义风险
- 修改建议

评分标准：

- `4` 分：三层区分清楚，没有混写
- `3` 分：基本区分清楚，少量混杂
- `2` 分：能看出在分层，但边界混乱
- `1` 分：多数内容混在一起
- `0` 分：没有分层，只有泛泛评论

### B. 证据锚定

判断模型能否把结论锚定到具体材料，而不是空泛表达。

看它是否能回到：

- `wire.svg`
- `spec.md`
- `project.flow.mermaid`
- 具体分区 / 具体节点 / 具体规则

评分标准：

- `4` 分：绝大多数结论都有明确锚点
- `3` 分：主要结论有锚点，少量概括偏空
- `2` 分：有些锚点，但很多判断仍在泛讲
- `1` 分：几乎不引用具体对象
- `0` 分：纯主观看法

### C. 页面类型判断

判断模型是否先识别当前页面属于哪一类，再给出对应审查。

重点看它会不会：

- 把 dashboard 当列表页审
- 把 detail-form 当抽屉页审
- 把 list + drawer 当成纯静态布局页审

评分标准：

- `4` 分：页面类型判断准确，审查重点完全匹配
- `3` 分：类型基本判断对，少量重点偏移
- `2` 分：能识别大类，但重点经常跑偏
- `1` 分：类型判断明显不稳
- `0` 分：页面类型完全错位

### D. 风险命中率

判断模型是否抓到了 L1 最该抓的问题，而不是停留在表面。

应优先命中的风险包括：

- 主任务和模板选择是否一致
- 浮层方位和交互上下文是否一致
- 状态表达是否足够可见
- review_focus 是否真的可审
- excluded 是否合理

评分标准：

- `4` 分：命中主要风险，且没有被次要表象带偏
- `3` 分：命中大部分风险，遗漏少量关键点
- `2` 分：只命中一部分，或把次要问题当成主要问题
- `1` 分：只看表面，不抓核心风险
- `0` 分：几乎没有有效风险判断

### E. 修改建议质量

判断模型给出的建议是否：

- 足够小
- 足够具体
- 真能提高审查或实现稳定性

评分标准：

- `4` 分：建议最小、具体、可执行
- `3` 分：建议基本有用，偶尔略泛
- `2` 分：建议方向对，但粒度偏大或偏空
- `1` 分：建议大而空，难落地
- `0` 分：几乎没有可用建议

## 3. 总分解释

### 17~20 分

可直接作为团队参考输出。

说明：

- 模型已经能稳定区分结构问题和语义风险
- 结论有锚点
- 建议足够小且有效

### 13~16 分

基本可用，但还需要人工二次过滤。

常见情况：

- 类型判断对，但证据锚点不够
- 风险判断有价值，但建议偏泛

### 9~12 分

有一定参考价值，但不适合作为稳定审查基线。

常见情况：

- 能复述页面结构
- 但抓不住关键风险
- 或者建议过大、过空

### 0~8 分

不建议采用。

常见情况：

- 页面类型判断错位
- 不区分确定性问题和语义风险
- 大量空泛评价

## 4. 最小通过标准

如果你不想每次都细打分，至少可以用这 4 条做简单通过判断。

一份 AI review 至少要满足：

1. 能区分 `Findings` 和 `Semantic Risks`
2. 至少 2 条结论能锚定到具体文件或字段
3. 没有把页面类型审错
4. `Minimal Fixes` 不超过 3 条，且都能落地

只要其中 1 条不满足，这份输出就不应作为“高质量审查”保存。

## 5. 三类页面的附加观察点

### 列表页 + 抽屉

额外看模型是否关注：

- 筛选区主任务
- 表格默认排序 / 空态 / 批量动作
- drawer 的 trigger / close / afterClose

### 详情页 + 确认弹窗

额外看模型是否关注：

- dialog 为什么比 drawer 更合适
- 表单分组是否成立
- 提交前确认和提交后回落

### 仪表盘 + 任务表

额外看模型是否关注：

- 卡片区 / 图表区 / 任务表的主次关系
- pending / error 的可见表达
- 总览页是否被误导成列表页或操作页

## 6. 推荐使用方式

建议这样用 rubric：

1. 先让模型按 [ai-review-prompt.md](/home/zhaocj/ws/opencode-skill/skills/shadow-l1-wire/references/ai-review-prompt.md) 输出 review
2. 再由人按本 rubric 快速打分
3. 把高分输出作为后续 prompt / 模型选择基线

## 7. 一句话原则

好的 rubric，不是把审查变成机械打分，而是让“哪些 AI review 真的有价值”变得可比较、可复用。
