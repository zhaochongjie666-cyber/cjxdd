# L5 Semantic Gate Prompt

用于 L5 第二轨 Gate（独立语义审查）。

## 输入
- L1: `spec.md` + `project.flow.mermaid`
- L5 Plan: `harness-plan.md`
- L5: 真实代码 + 测试代码

## 目标
判断 L5 是否真正兑现了 L1，而不是只把 Harness 计划补成了"能跑"。必须满足：
1. **规则兑现深度**：L1 的关键规则是否在实现和测试中都有直接落点，而不是只在文件头写了 `@implements`？
2. **错误/状态/权限/副作用兑现**：L1 明确的错误码、状态迁移、权限约束、外部依赖策略、副作用是否在代码中可观察、可测试？
3. **测试诚实度**：测试是否真正验证了业务语义，而不是空函数 / 永真断言 / 只测 happy path？

## 审查问题（必须逐项回答）
1. 抽查 3-5 条关键 L1 规则，是否在实现代码和测试代码中都能找到直接对应？
2. L1 中有错误码/错误文案的规则，实现中是否返回了正确的错误码，测试中是否验证了？
3. L1 中有状态变化的规则，实现中是否实现了状态机，测试中是否有状态转换断言？
4. L1 中有权限/角色约束的规则，实现中是否有鉴权/授权逻辑，测试中是否有越权场景？
5. L1 中有外部依赖/副作用的规则，实现中是否有调用路径/降级/重试策略，测试中是否验证？
6. 是否存在存根（pass/return None/TODO）占位，而对应的 L1 规则要求完整实现？
7. 测试是否覆盖了主流程以外的异常/边界/拒绝/越权场景？
8. 安全项（输入校验、敏感数据、权限检查）是否有实际代码而非空壳？

## 判定规则
- 只要"规则兑现深度"中存在关键规则只存在于文件头注释而未真正实现或测试，直接 FAIL。
- 不允许只给笼统评价，必须给具体证据。
